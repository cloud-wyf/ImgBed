# 图片回收

仅扫描 `D:/Notes` 下的 `.md` 和 `.markdown` 文档。图片链接以当前图床 `/file/` 地址为准。新上传图片直接放在 `typora/`；旧年月目录递归参与核对，已有文档链接继续有效。

每天完整扫描一次，首次发现无人引用时开始计时。引用重新出现时计时清零。连续 30 天无人引用的图片通过图床接口复制到同级 `回收站/`，核对大小、SHA-1 与管理记录，再永久删除原路径所有文件版本及删除标记。回收站副本不自动删除，也不自动恢复引用。

无人引用的计时保存在本机 `recycle-state.json`，不每天写入云端。初始化不根据上传时间推算历史引用：首次完整核对起至少等 30 天。读取目录失败、没有读到笔记、文档在读取时变化或云端清单不完整时停止。本机连续超过 2 天没有成功核对，之前的无人引用计时重置。

本机 `upload-index.sqlite3` 记录最终上传内容的完整 SHA-256 和最近上传/复用时间。刚上传或复用的图片即使还未保存进文档，也会重新开始至少 30 天的无人引用等待。上传与回收共用进程锁；成功回收后清除该图片的去重索引。之后再次插入同图会重新上传，不从回收站自动恢复。索引从本次改造后的上传开始建立，旧图不会自动补建。

回收前重新扫描已保存的文档。尚未保存到磁盘的编辑内容和 `D:/Notes` 外部引用无法识别。图片不能用于未纳入扫描的文章、其他电脑文档或外部分享，否则仍可能按本地无人引用判定。

复制与永久删除采用 B2 服务端操作，不下载图片。复制期间暂时同时保存两份；成功清除源版本后只保留回收站副本。每日扫描只获取图床元数据；有待回收文件时才授权 B2 并核对/删除版本。上传命中去重索引时另行查询图床记录和 B2 元数据，也不下载图片，但会增加少量 API 请求。

## 手动检查

Windows 计划任务 `TyporaImgBed-每日图片回收` 每天北京时间 20:00 在当前用户已登录时后台运行，不弹出窗口。错过时间后在可运行时补执行，不主动唤醒电脑。任务执行 `recycle.py --apply`，单次最多 30 分钟。

预览（不保存计时、不回收）：

```powershell
& "C:/Users/sqwuy/.version-fox/cache/python/current/python.exe" "D:/Program Files/TyporaImgBed/recycle.py"
```

执行核对并回收到期图片：

```powershell
& "C:/Users/sqwuy/.version-fox/cache/python/current/python.exe" "D:/Program Files/TyporaImgBed/recycle.py" --apply
```

最近一次结果保存在 `recycle-report.json`。图片移入回收站的目标名带唯一前缀，以免同名覆盖；不在回收站创建子目录。操作中断时，本地状态记录待完成任务，下次核对副本与源版本后继续。若中断任务的源链接重新出现引用，停止并在报告中提示人工处理，不自动恢复。

## 用户删除回收站

回收站交给用户检查。现有图床后台的普通删除只隐藏 B2 文件，不能立即释放容量。真正永久删除时，可在 B2 官网查看该回收站文件的版本并删除所有版本；随后删除图床后台对应记录。不要只删除最新删除标记，因为这会使旧版本重新可见。

`recycle-config.json` 配置扫描根目录、30 天阈值和单次最多回收 100 张的上限。扫描范围变化会停止任务，需要重新初始化本地计时。凭据沿用本机 DPAPI 文件，不另存明文。
